  Selected Single Adapter Path for Minimal Publish

  Codex adapter (runtime/adapters/codex_adapter.py).

  Reason: It provides the stronger structural guarantee. It enforces output schema via --output-schema CLI flag (codex_adapter.py:396), which is a hard constraint enforced by the Codex CLI tool itself.   If the Claude SDK adapter is kept, it must be explicitly marked as experimental with documented boundary conditions.

  Justification:

  The core runtime surface (event store, projector, processing gate, validators, tasks, slice builder, canonicalization, worker layer, schemas, rules, configs) is factually complete and self-contained. Every architectural invariant — event sourcing, validation-before-acceptance, deterministic replay, externalized memory, deny-by-default policy — is implemented with verifiable code evidence. The Codex adapter provides structurally
   enforced output.

  However:

  1. The default CLI path uses the Claude SDK adapter (cli.py:338-339), which has weaker enforcement. Publishing without marking this would misrepresent the enforcement level users get by default.
  2. The Claude SDK adapter supports max_agent_turns=20 (claude_agent_sdk_adapter.py:70), which is a bounded agent loop — contradicted by the system's own non-goals (docs/non_goals.md:159).
  3. The repository contains ~30 files of v1.3 planning/adaptive infrastructure (runtime/planning/, runtime/adaptive/, etc.) and ~114 docs files that are development artifacts. A clean minimal publish requires explicit exclusion of these.
  4. No public-facing documentation exists (no README.md, no ARCHITECTURE.md). Three new documents must be written.

  The core runtime is ready. The repository as a whole requires scope trimming and experimental markers before publication.
